локальная версия

Установка и запуск

Готовый комплект: бинарники сервера и воркера, собранный дашборд и скрипты. Rust, Node.js и сборка на вашей машине не нужны.

Демо-режим теперь доступен всем Скачайте комплект и запустите у себя — без лицензии он работает в демо-режиме: вход без ключа, проверка одного файла (см. шаг 5). Полный доступ — с файлом лицензии.
Лицензии — по запросу Офлайн-лицензия — файл .lic: ключ проверяется на вашем сервере без выхода в интернет, в нём записаны владелец и срок. Лицензия открывает всё — ревью кода и развёртки, пентест, scope, аудит; без неё комплект работает в демо-режиме. Чтобы получить ключ — напишите нам.

Что нужно

  • Linux x86_64: Debian/Ubuntu, Fedora/RHEL, Alpine или Arch — пакеты setup ставит сам.
  • glibc не старше той, на которой собран комплект (строка glibc выше). Если сервер пишет «GLIBC_… not found» — напишите нам, соберём под ваш дистрибутив.
  • PostgreSQL 13+ — setup поднимет локальный (нужен sudo) или используйте свой.
  • По желанию: docker + compose (пентест в песочнице), gitleaks, nuclei, Ollama или ключ облачной нейросети.

Инструкция

  1. Скачайте и распакуйте

    Архивом или через git — содержимое одинаковое.

    curl -L -o zdc.tar.gz https://github.com/ZDC-System/ZDC-bin-release/archive/refs/heads/main.tar.gz
tar xzf zdc.tar.gz && cd ZDC-bin-release-main
# или: git clone https://github.com/ZDC-System/ZDC-bin-release.git && cd ZDC-bin-release

  2. Проверьте целостность

    Каждая строка должна закончиться «OK».

    sha256sum -c SHA256SUMS

  3. Подготовьте машину

    Ставит недостающие пакеты, поднимает PostgreSQL (роль zdc, база reports), создаёт scripts/zdc.env с паролем БД и ключом шифрования, ставит анализаторы. Повторный запуск ничего не перетирает.

    ./zdc.sh setup
# без анализаторов:      ZDC_SKIP_ANALYZERS=1 ./zdc.sh setup
# БД на другой машине:   export ZDC_EXTERNAL_DB=1 и DATABASE_URL в scripts/zdc.env

  4. Запустите и активируйте

    Скрипт поднимает сервер, дашборд и воркер. Есть файл лицензии — подключите его командой license. Откройте http://127.0.0.1:5173 и введите ключ ZDC_LICENSE_USER из файла лицензии (или загрузите файл целиком) — ключ сохраняется в браузере. Без лицензии — кнопка «Демо-режим».

    ./zdc.sh license acme.lic   # если есть файл лицензии
./zdc.sh start

  5. Демо-режим — включён по умолчанию

    На экране активации есть кнопка «Демо-режим»: вход без ключа, ревью кода одного загруженного файла (до 512 КБ), выбор нейросети и запуск воркеров. Пентест, scope, аудит, расписание и отчёты, созданные по лицензии, в демо недоступны. Не нужен — выключите одной строкой.

    echo 'export DEMO_MODE=0' >> scripts/zdc.env   # выключить демо
./zdc.sh restart

  6. Выберите нейросеть

    По умолчанию — локальная Ollama: код не покидает сервер. Модель, облачного провайдера и ключи API меняют в дашборде на странице «Нейросеть». Берите модель от 7B — маленькие пропускают уязвимости. Облачный провайдер получает фрагменты кода и находки.

    ollama pull gemma3

Команды

./zdc.sh statusсостояние компонентов и проверка здоровья ./zdc.sh logs serverхвост журнала сервера (или worker) ./zdc.sh restartперезапуск после правки scripts/zdc.env ./zdc.sh stopштатная остановка — воркер сносит песочницу пентеста

Данные и журналы — в .zdc-data/. Ключ SECRETS_KEY в scripts/zdc.env не теряйте и не меняйте: им зашифрованы ключи нейросетей. Наружу дашборд открывайте только через прокси с TLS (nginx), оставив DASHBOARD_BIND на 127.0.0.1. Подробности — в README комплекта.

Установка в Windows (WSL)

Комплект работает в WSL 2 так же, как на обычном Linux. Дашборд открывается в браузере Windows.

  1. Поставьте WSL с Arch Linux

    В PowerShell от имени администратора. Arch — потому что комплект собран под glibc 2.44: в Ubuntu и Debian из WSL glibc старее, и сервер не запустится (нужна отдельная сборка — напишите нам). Нужен WSL 2.4.4 или новее.

    wsl --update
wsl --install -d archlinux
wsl -d archlinux

  2. Обновите систему и включите systemd

    setup запускает PostgreSQL через systemd. Вторая команда включает его, если он выключен; после неё перезапустите WSL (wsl --shutdown в PowerShell) и войдите снова.

    pacman -Syu --noconfirm
[ "$(ps -p 1 -o comm=)" = systemd ] || printf '[boot]\nsystemd=true\n' >> /etc/wsl.conf

  3. Установите и запустите в домашнем каталоге

    Распаковывайте в файловую систему WSL (~), а не в /mnt/c: на дисках Windows теряются права на запуск и всё работает медленно. Дальше — шаги 1–4 инструкции выше.

    cd ~
curl -L -o zdc.tar.gz https://github.com/ZDC-System/ZDC-bin-release/archive/refs/heads/main.tar.gz
tar xzf zdc.tar.gz && cd ZDC-bin-release-main
sha256sum -c SHA256SUMS && ./zdc.sh setup && ./zdc.sh start

  4. Откройте дашборд в Windows

    Откройте http://127.0.0.1:5173 в браузере Windows — WSL пробрасывает localhost сам. Если страница не открывается, включите зеркальную сеть: добавьте в %UserProfile%\.wslconfig строки ниже и выполните wsl --shutdown.

    [wsl2]
networkingMode=mirrored

  5. Нейросеть и пентест

    Ollama ставится прямо в WSL; с зеркальной сетью подойдёт и Ollama для Windows на 127.0.0.1:11434. Для пентеста в песочнице нужен docker: в WSL или Docker Desktop с интеграцией WSL для этого дистрибутива.

    pacman -S --noconfirm ollama docker docker-compose
systemctl enable --now ollama docker
ollama pull gemma3

  6. После перезагрузки Windows

    WSL не стартует сам — запустите систему одной командой из PowerShell (или добавьте её в автозагрузку через Планировщик заданий). Пока терминал WSL закрыт, Windows может остановить дистрибутив — держите его открытым или проверяйте ./zdc.sh status.

    wsl -d archlinux -- bash -lc "~/ZDC-bin-release-main/zdc.sh start"
