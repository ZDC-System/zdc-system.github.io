# ZDC Systems — лендинг

Статическая страница проекта для GitHub Pages: без сборки и зависимостей —
`index.html`, `style.css`, `app.js`, `i18n.js` и скриншоты дашборда в `assets/`.

## Стиль

Фирменный стиль — как в дашборде и логотипе: угловатые формы со скошенными углами (у
панелей, карточек, кнопок и меток срезаны левый верхний и правый нижний углы —
`clip-path` с `--ch-l/--ch-m/--ch-s`, как `--chamfer` у кнопок дашборда; диагональ рамки
дорисовывает фоновый градиент), наклонные штрихи логотипа (перед подписями разделов, в
заголовках окон, крупно на фоне), палитра тёмной/светлой темы дашборда, шрифты Inter и
JetBrains Mono. Всё это — последний блок `style.css` («Фирменный стиль ZDC»), он
перекрывает прежние скругления; новые элементы оформлять так же (без `border-radius`,
кроме точек критичности). Наружные тени у срезанных элементов не видны — свечение
рисуется внутренним контуром или `filter: drop-shadow`. Так же оформлен питч
(`Zero-Day-Check/pitch`).

## Что внутри

- **Стартовая страница** (`#intro`) — открывается первой (адрес без якоря) и по клику
  на логотип: заголовок, журнал воркера, три карточки, без шапки. «Попробовать демо»
  ведёт на страницу установки (`install.html`), «Узнать больше» — к основному лендингу.
  Прежнего hero нет — основной лендинг начинается с бегущей строки и демо-скана.
  Любой якорь раздела (`#scanner`, `#cloud`…) открывает основной лендинг сразу.
- **Демо-скан** — Flask-приложение, по которому проходит сканер: находки по
  критичности, токен GitHub вычищается `redact` прямо на глазах. Токен
  генерируется в браузере — в репозитории нет ничего похожего на настоящий секрет.
- **Режимы**, **конвейер** (SVG с бегущими пакетами, описание узла по наведению),
  **песочница пентеста**, **орбита провайдеров** (локально / облако),
  **галерея** скриншотов — переключается вместе с темой, **принципы** (карточки
  переворачиваются), **развитие проекта** — хроника по датам из журнала разработки
  (линия заполняется при прокрутке, фильтр по направлениям, скриншоты увеличиваются),
  **анонс ZDC Cloud** (`#cloud`, «скоро»: вход через Google/GitHub, личный аккаунт или
  организация, покупка лицензии в личном кабинете, выгрузка отчётов; снимки кабинета и
  регистрации и покупки (цены размыты — тарифы условные) — `assets/shots/{light,dark}-cloud-{account,buy,register}.webp`, переключаются
  с темой; пересъёмка — `cloud_web/e2e/landing-shots.mjs`; плашка-ссылка в hero и пункт
  «Облако» в шапке; облако описано как будущее — ничего не обещать сверх сделанного),
  **локальная версия и сотрудничество** — как проходит внедрение и почта для
  предложений (misanaproger@gmail.com и ziron0901@gmail.com; кнопка «Связаться» в шапке
  пишет обоим, CTA в финале, подвал) и объявления «демо-режим доступен всем» (без
  лицензии комплект работает в демо) / «лицензии — по запросу».
- Провайдеров LLM — 12 (орбита в `app.js::orbit`, счётчик и `hero.c2`); хроника —
  `META` в `app.js` + `hist.items` в `i18n.js` (у каждой даты тегов столько же, сколько
  пунктов), последняя дата — 7 ноября (снимок — список отчётов). Картинкам с
  `loading="lazy"` задавать размер (`aspect-ratio`) — иначе при прокрутке съезжает вёрстка
  и якорные ссылки промахиваются.
- **Страница «Установка»** (`install.html` + `install.js`) — скачивание комплекта из
  открытого репозитория `ZDC-System/ZDC-bin-release` и инструкция запуска (setup → start →
  `./zdc.sh license <файл .lic>` при наличии лицензии и активация ключом `ZDC_LICENSE_USER`,
  без лицензии — демо-режим (включён по умолчанию, `DEMO_MODE=0` выключает), нейросеть,
  команды). Страница описывает лицензионную сборку — публиковать вместе с комплектом
  `bin_release` той же версии. Ссылки в разметке
  ведут на архив ветки `main`; скрипт при загрузке спрашивает GitHub API — если появится
  релиз, кнопки переключатся на его архив, — и показывает версию/glibc из `VERSION`.
  Без сети или при лимите API (60 запросов/ч с адреса) остаются ссылки на `main`.
- Скриншоты — только настоящие снимки дашборда (Playwright, `pitch/scripts/shots.mjs`)
  без макетов устройств; данные на них — демонстрационные (`pitch/scripts/seed.py`).
- Языки RU / EN / UZ (`i18n.js`; язык браузера по умолчанию), светлая и тёмная
  тема, `prefers-reduced-motion`, адаптив до 360px.
- Пасхалка: код Konami (↑ ↑ ↓ ↓ ← → ← → B A) или клик по нему в подвале.

## Локально

```bash
python3 -m http.server 8000   # http://localhost:8000
```

## Публикация

1. Создать репозиторий (например, `ZDC-Systems/zdc-systems.github.io` — тогда адрес
   будет `https://zdc-systems.github.io/`, или любой другой — `…/имя-репо/`).
2. Запушить содержимое каталога в `main`.
3. Settings → Pages → Source: **GitHub Actions**. Workflow `.github/workflows/pages.yml`
   публикует страницу при каждом пуше.

Все пути относительные, поэтому страница работает и в корне домена, и в подкаталоге.
Скриншоты пересобираются: стенд (Postgres + `analitics_service`, собранный с
`ZDC_LICENSE_PUBKEY` тестового ключа издателя, с `DASHBOARD_DIR` и `ZDC_WORKER_KEY`; демо
включён по умолчанию). Простых пользовательских токенов больше нет: в `seed.py` (`USER`) и
`shots.mjs` (`zdc.apiToken`) подставить ключ `ZDC_LICENSE_USER` из лицензии, выпущенной
`zdc_issuer` этим ключом, в `seed.py` `WORK` — значение `ZDC_WORKER_KEY` (сейчас там
старые токены); `python3 pitch/scripts/seed.py` → JSON с id отчётов,
`BASE=http://127.0.0.1:<DASHBOARD_BIND> node pitch/scripts/shots.mjs '<json>'` → PNG
(в т. ч. `*-demo` — форма демо-режима), затем webp: 1600×1000, телефон — 560×1212
(`assets/shots/{light,dark}-<имя>.webp`).
